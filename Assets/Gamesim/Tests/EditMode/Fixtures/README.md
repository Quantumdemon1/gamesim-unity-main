# Web parity fixtures

`WebParityFixtures.json` contains expected results captured by executing the preserved Gamesim TypeScript source, bundled in memory with esbuild. Its expected values are not recomputed by C# tests. `WebSourceManifest.json` identifies the original source hashes and the full reference fixture hash.

The generator and complete reference capture live in the development task at `work/unity-port-reference/generate-fixtures.mjs`, `collect-fixtures.ts`, `golden-fixtures.json`, and `source-manifest.json`. Running the generator twice produced byte-identical JSON. The bundle uses default balance settings because the Node process has no browser localStorage overrides; development-only logging is disabled.

Proven arithmetic: UTF-16 FNV-1a hashing, Mulberry32 samples/state restoration, Fisher-Yates order, positive-player social adjustment, independent reciprocal relationship samples, [-100, 100] clamp, all seven promise impact types, social success/failure arithmetic, and five weighted competition categories including nominee clutch and player bonuses. The complete weighted fixtures retain original participant order, the initial competition-name RNG draw, Crapshoot's second draw, and stable placement ordering.

Two web competition implementations have different contracts. Legacy `competition-system.ts` uses a single stat and chooses the later competitor on equal scores. `competition/competition-runner.ts` uses category weights, clutch/luck/player bonuses, and stable descending sorting so the earlier competitor wins a tie. The native episode uses the weighted arithmetic leaves. Its player challenge bonus policy and episode scheduling are native policies, not proof of whole-run web parity.

These fixtures do not prove parity for the entire web reducer, private runtime caches, promise lifecycle, receipts, relationship arcs, NPC voting strategy, or web-save migration. The broader reference capture includes nomination/veto authority and six NPC vote evaluations for subsequent coverage. In particular, the web promise arithmetic accepts a loyalty argument but the old PromiseSystem caller omits it (default 5), applies a one-way relationship event, and has no evaluation branch for `veto_use` or `hoh_protection`.

All numerical rules use doubles. JavaScript round-to-nearest ties toward positive infinity; C#'s default midpoint-to-even rounding is not interchangeable. Negative half examples are exercised by promise impact captures.

RNG fixtures include the original unsigned integer numerators (`expectedUInt32`). Tests compare each C# sample multiplied by 2^32 to that integer exactly, avoiding a one-ULP discrepancy in Unity's decimal JSON parser without weakening bit-for-bit RNG parity.
