# Old-save acceptance

The owner's decision (2026-10-15): old-save acceptance means committed fixture saves, one per save version and rules
combination, that load, migrate, validate, replay to the recorded digest and render every reader without leaks. This
is the gate before any schema-29 work (role and action-point dialogue, B9 tuning, the All-Star rebuild).

Where it stands (lane W2-saves, 2026-10-15):

- **Every cell a surviving build could write has a fixture**: 19 real saves, 30 saves generated by the schema's own
  build, two real career files, and one save refused on purpose. `OldSaveAcceptanceTests` holds all of them
  (section 4).
  - Schemas 2 to 5 were written by no commit here. Their fixtures were generated by the Codex port's own source
    snapshots of those versions, kept outside the repository (2.1).
  - Only schemas 1 and 8 have no fixture: no build that wrote 1 survives, and no build ever wrote 8 (1.2).
- **Every real save found loads**: all 116 GamesimVerify files, the owner's 98 local saves (schemas 12 to 28) and
  Codex's 10 schema-22 run saves, backups included. Each loads in this build and plays to its end. Only the 19 curated
  saves are committed (2.2).
- **One real defect found and repaired**: a schema-22 save from that version's first builds was refused by every later
  build (finding F1).
- **Two unversioned replay breaks found** in the history, both accepted fixes. The fixtures record them and are
  referenced past them (F2, F3).
- **One schema number has two meanings**: the story-arcs line's own 14. This build refuses it whole (F4).
- **Codex's 17 reader holds** map to a test here that pins all seventeen readers on every fixture. **L01 to L16** are
  custody of Codex's native capture host and are closed as process only (section 5).
- **The Frozen28 reader compiles and passes**: under net10 with warnings as errors, 4,781 of 4,781 cases, and it
  accepts every fixture. What landing it takes is in section 6.

Sources: `Assets/Gamesim/Runtime/Persistence` (EpisodeSaveStore, EpisodeSaveMigrations, FrozenEpisodeV*, CareerLedger),
`Assets/Gamesim/Simulation/ShippedRules.cs`, the history of `EpisodeState.cs`, and `Tools/OldSaves` runs against

## 2. How the fixtures were made

**Real saves (19 and 2 careers).**

- Byte-for-byte copies of the archived `GamesimVerify` folder (`D:\ClaudeScratchArchive\2026-10-15-consolidation`,
  identical to `D:\GamesimVerify`). Each is the verification walks' standalone player save, CRLF and checksum intact.
  The folder's `.gitattributes` keeps them `-text`.
- **Checked for anything typed.** The player is "You" in every file. The cast is the shipped roster. The only typed
  text is the walk's fixed QA speech. No path appears in any save.
- No name was replaced, so nothing had to be re-recorded.
- `verification.json` and `season-verification.json` are not committed.
- Where a schema had several saves, the choice preferred a mid-season state and a varied week: w1 HoH,
  the w1 eviction speeches, the final speeches. The schema-21 default cell reuses `V21StandaloneProfileSave.json`,
  which is the same file.

**Generated saves (30).** 26 by commits of this repository, and 4 (schemas 2 to 5) by the Codex port's source
snapshots, as 2.1 describes.

- `sh Tools/OldSaves/build.sh <commit> <worktree> <out>` creates a detached worktree under `D:\GamesimW2-saves-gen`
  with only that commit's `Simulation` and `Runtime/Persistence` checked out. It compiles them with the recorder,
  using the editor's Roslyn, the Simulation assembly's references and defines, and C# 9.
- The recorder runs under the editor's Mono, the runtime EditMode replays on.
- `recorder.exe generate <out> <seed> <size> <director|default> <week> <phase>`:
  1. starts the season as that build did (`Rules.*.cs` is its `StartSeason`, line for line);
  2. walks it to the stop point with the fixed walker;
  3. saves it with that build's own `EpisodeSaveStore`.
- Every manifest entry names the writer commit and the arguments.
- The temporary worktrees are removed with `git worktree remove --force`.
- **Two departures from a player's save**:
  - The session id is fixed (`oldsave-…`), so a regeneration writes the same state.
  - The director's `CharacterAppearanceSnapshots.Materialize`, a Runtime call, is not run, so appearances are null,
    as on any season built outside the director. Validation accepts both.

**The walker.**

- `EpisodeEngineTests.NextCommand`, the plain legal walk, line for line.
- Up to two conversations in each social week, the target picked by the season's revision.
- Under the finale rules, the first response a jury question offers.
- Schemas 2 to 7 compile it without eviction stages (`OLDSAVE_BEFORE_SCHEMA8`), and schema 2 without the diary room
  (`OLDSAVE_BEFORE_SCHEMA3`).
- It is deterministic in the state alone. Only the recorder runs it: a replay reads the script.
- Every command is a player command applied through `EpisodeEngine.Apply`. No real-time NPC tick is in a script
  (the director's free-roam clock), so a replay is exact.

**The digest** (`Assets/Gamesim/Tests/EditMode/OldSaveTrace.cs`, one source compiled into the recorder and the tests).

- A checkpoint is the state's public fields:
  - taken down to the reference build's schema, removing what schemas 21 to 28 added after checking each still holds
    its migration's off value;
  - written with sorted keys;
  - hashed three ways.
- The three hashes:
  - **season**: prose blind, without the narrated `events` log;
  - **state**: prose blind;
  - **text**: verbatim.
- The checkpoints are the loaded state and the state after every command.
- **The season digest is the cross-build gate.** It must equal the reference build's.
- **The state and text digests are this build's, pinned at curation.** They differ from the reference build's only
  where presentation passes moved old seasons on purpose (F7). The manifest records both values and the first
  checkpoint that differs.

## 3. Findings

**F1. Schema 22 has two shapes, and the first was refused. Repaired.**

- What changed inside the version:
  - C7 (c55a4535, 10-02 16:22) added `deals[].linkedDealId`.
  - The C5 review fix (d44bf492, 10-03) added `alliances[].playerJoined`.
  - Both came after schema 22's first build (5eedae12/50ebd57c, 10-02), without a new version.
  - They rewrote the v21→v22 step and `FrozenEpisodeV22` to require both fields.
- The effect: a save written by builds 50ebd57c to d44bf492^ that held a deal or an alliance was refused by every
  later build as "Invalid historical schema 22 data". The generated `s22-director-early-w2-campaign` (5eedae12) shows it.
- **The repair**, `FrozenEpisodeV22.WithLaterFields`, used by `UpgradeV22ToV23`:
  - A list where every row lacks the field gains it on every row, as a literal:
    - null: no deal of those builds was a negotiation's;
    - false: a pact's member order still says who founded it, as that build read it.
  - A mixed list is still refused.
  - The input is never changed.
- `PersistenceV23MigrationTests` is adjusted to match:
  - The two "missing" cases now use a mixed list, and assert the schema-22 contract's own message.
  - A new test proves the first shape migrates exactly as the last.
- Nothing else changed: no other schema's first and last builds differ in shape (1.2).

**F2. The story's agency retune (8a5f2ecc, 09-28 13:51) moved story-v9 seasons without a version.**

- Affected: a schema-20 director season from 7f398b94, and schema 10, 11 and 14 saves migrated by builds 7f398b94 to
  8a5f2ecc^. They continue otherwise than those builds played them.
  - `s20-director-w2-veto-meeting`: from checkpoint 8.
  - s10: from checkpoint 47.
  - s11: from checkpoint 23.
  - s14: from checkpoint 19.
- Unaffected: seasons with story rules 6 to 8 (every real schema-16 to 19 save), and the schema 6, 7, 9, 12, 13 and 15
  cells. 7f398b94 and this build agree on all of them.
- Bisected: 7b9e4b60 differs, 8a5f2ecc matches.
- An accepted fix; the fixtures are referenced at 8a5f2ecc and record 7f398b94's digest as evidence.

**F3. The arcs change-paths merge (8ffc99cd, 10-10 15:28) moved all-week seasons without a version.**

- A mode-1 all-week season saved at 27b21b28 continues otherwise from checkpoint 13. 27b21b28, b25bfeba and
  de88a8bb all play it as it was saved; 8ffc99cd and every build since play it this way.
- The window of affected saves is 27b21b28 to 8ffc99cd^: the all-week rules shipped 10-09 09:09, the merge landed
  10-10 15:28.
- The merge keeps house-to-house changes out of the player's arcs (memory "Arcs belong to the player"). It is an
  accepted fix.

**F4. "Schema 14" has two meanings.**

- The two lines:
  - The game-flow line wrote Have-Nots as 14 (7fc031fb).
  - The story-arcs line wrote the story's fields as 14 (52cb23df, the main line's only schema-14 commit).
- They met at 76654f3b as 14 (Have-Nots), 15 (strategy) and 16 (story).
- This build refuses a story-arcs 14 file whole: "Missing schema 14 field." The refusal leaves it untouched.
  `AnOldSaveFromABranchsOwnSchemaNumberIsRefusedAndLeftAsItWas` holds that.
- **Owner's call.** Supporting such a file needs its own route, 14-story to 16 with the Have-Not and strategy
  literals. It would only ever carry saves from one day's branch builds.

**F5. By design, older saves continue differently on older builds.**

- The migration steps to 9–12 and 16–20 start their rules the week after the save's.
- The builds that wrote schemas 16 to 19 therefore play the following weeks under fewer rules than this build. The
  current build refuses their scripts from week 2: command 29 on the default saves, command 15 on levers18.
- That is why the reference for those saves is 7f398b94, the first build whose migration ends with this build's rule
  set.

**F6. Schema 16's step is not frozen.**

- `UpgradeV15ToV16` opens the story world with the live `EpisodeEngine.EnableStory` and `StoryRules.Current`.
- So a schema 6 to 15 save's continuation depends on the build loading it. A later `StoryRules.Current` bump would move
  every such season.
- The acceptance test pins today's value (`AssertRulesKept`).
- **Recommendation.** Freeze the step's story rules version at 9, as every other step's literals are frozen. This is
  a code change for the persistence owner, not made here.

**F7. Presentation passes reach old seasons on purpose.**

- Two kinds:
  - Ballot privacy (UI-UX-PASS-PLAN B0): a vote-reveal line is now logged to its voter alone.
  - Writing passes: for example the Talk line, decision 19.
- Both change the `events` log of any season played on in this build. That is why the cross-build gate is the
  season digest, and the state and text digests are pinned instead.
- Finished saves and every save from schema 26 on match the reference build in all three digests.

**F8. The ballot sentinel can read an undated line against the wrong week.**

- `BallotPrivacyTests.NamesTheBallot` holds an undated line against every week's hidden ballots.
- When a voter cast the same ballot twice, it flagged a line telling the week the player knows:
  - the finalist read's "Quinn · Emma · voted to evict them" (s21);
  - an old public reveal line (s07).
- The acceptance test dates the weekly recap's lines and excuses an undated line only where the same ballot is known
  in another week.
- `BallotPrivacyTests` itself is unchanged and could meet the same case.
