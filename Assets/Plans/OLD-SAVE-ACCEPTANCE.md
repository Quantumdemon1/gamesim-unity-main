# Old-save acceptance

The owner's decision (2026-10-15): old-save acceptance means committed fixture saves, one per save version and rules
combination, that load, migrate, validate, replay to the recorded digest and render every reader without leaks. This
is the gate before any schema-29 work (role and action-point dialogue, B9 tuning, the All-Star rebuild).

Where it stands (lane W2-saves, 2026-10-15; review fixes 2026-10-16):

- **Every cell a surviving build could write has a fixture that replays it**: 19 real saves, 40 saves generated by the
  schema's own build, two real career files, and one save refused on purpose. `OldSaveAcceptanceTests` holds all of
  them (section 4).
  - **Schema 29 included** (2026-10-22, section 6 step 5): three saves written and recorded by the schema-29 build
    itself (60d8f629), one for each commitment mode at dialogue rules 0. `OldSaveTrace` knows schema 29's literals and
    `Newest` is 29 (2.3).
  - A cell counts only a fixture saved in a week, before the finale, whose recorded script plays the season on from
    there. The eight real saves made at the final speeches or after the finale are read, never counted as their
    cell's replay (1.3).
  - Schemas 2 to 5 were written by no commit here. Their fixtures were generated by the Codex port's own source
    snapshots of those versions, kept outside the repository (2.1).
  - Only schemas 1 and 8 have no fixture: no build that wrote 1 survives, and no build ever wrote 8 (1.2).

  (never named, 2.2) and Codex's 10 schema-22 run saves, backups included. Each loads in this build and plays to

## 2. How the fixtures were made

**Real saves (19 and 2 careers).**

- Byte-for-byte copies of the archived `GamesimVerify` folder (`D:\ClaudeScratchArchive\2026-10-15-consolidation`,
  identical to `D:\GamesimVerify`). Each is the verification walks' standalone player save, CRLF and checksum intact.
  The folder's `.gitattributes` keeps them `-text`.
- **Checked for anything typed.** The player is "You" in every file. The cast is the shipped roster. The only typed
  text is the walk's fixed QA speech. No path appears in any save.
- No name was replaced, so nothing had to be re-recorded.
- `verification.json` and `season-verification.json` are not committed.
- Where a schema had several saves, the choice preferred a mid-season state and a varied week: w1 HoH,
  the w1 eviction speeches, the final speeches. The schema-21 default cell reuses `V21StandaloneProfileSave.json`,
  which is the same file.

**Generated saves (40).** 36 by commits of this repository, and 4 (schemas 2 to 5) by the Codex port's source
snapshots, as 2.1 describes. Seven of them were added on 2026-10-16 (review M3, m1): the director at mid-season for
schemas 17, 19 and 26, where the only director fixture was a finished save; schema 22's middle shape; and three of
schema 28's five director combinations (1.3). Schema 29's three were added on 2026-10-22, written by the 29 build
itself (2.3).

- `sh Tools/OldSaves/build.sh <commit> <worktree> <out>` creates a detached worktree under `D:\GamesimW2-saves-gen`
  with only that commit's `Simulation` and `Runtime/Persistence` checked out. It compiles them with the recorder,
  using the editor's Roslyn, the Simulation assembly's references and defines, and C# 9.
- The recorder runs under the editor's Mono, the runtime EditMode replays on.
- `recorder.exe generate <out> <seed> <size> <director|default> <week> <phase>`:
  1. starts the season as that build did (`Rules.*.cs` is its `StartSeason`, line for line);
  2. walks it to the stop point with the fixed walker;
  3. saves it with that build's own `EpisodeSaveStore`.
- Every manifest entry names the writer commit and the arguments.
- The temporary worktrees are removed with `git worktree remove --force`.
- **Two departures from a player's save**:
  - The session id is fixed (`oldsave-…`), so a regeneration writes the same state.
  - The director's `CharacterAppearanceSnapshots.Materialize`, a Runtime call, is not run, so appearances are null,
    as on any season built outside the director. Validation accepts both.

**The walker.**

- `EpisodeEngineTests.NextCommand`, the plain legal walk, line for line.
- Up to two conversations in each social week, the target picked by the season's revision.
- Under the finale rules, the first response a jury question offers.
- Schemas 2 to 7 compile it without eviction stages (`OLDSAVE_BEFORE_SCHEMA8`), and schema 2 without the diary room
  (`OLDSAVE_BEFORE_SCHEMA3`).
- It is deterministic in the state alone. Only the recorder runs it: a replay reads the script.
- Every command is a player command applied through `EpisodeEngine.Apply`. No real-time NPC tick is in a script
  (the director's free-roam clock), so a replay is exact.

**The digest** (`Assets/Gamesim/Tests/EditMode/OldSaveTrace.cs`, one source compiled into the recorder and the tests).

- A checkpoint is the state's public fields:
  - taken down to the reference build's schema, removing what schemas 21 to 29 added after checking each still holds
    its migration's off value (in the tests, a live schema-29 state is first admitted by `CurrentOldSaveTrace`, 2.3);
  - written with sorted keys;
  - hashed three ways.
- The three hashes:
  - **season**: prose blind, without the narrated `events` log;
  - **state**: prose blind;
  - **text**: verbatim.
- The checkpoints are the loaded state and the state after every command.
- **The season digest is the cross-build gate.** It must equal the reference build's.
- **The state and text digests are this build's, pinned at curation.** They differ from the reference build's only
  where presentation passes moved old seasons on purpose (F7). The manifest records both values and the first
  checkpoint that differs.
